## 两个独立问题

1. **计时错误：**c1 最后一篇先等待配额 118.639 秒，进入 HTTP 阶段仅 1.367 秒就被 120 秒请求定时器取消。配额等待原先处于 Ktor 定时器启动后的拦截器，导致测量不公平。旧数据保留，本轮全局结论仅作诊断。
2. **模型质量：**c1 的空文得到一个 session、三条训练动作，结构校验通过但“动作数为零”检查点失败。之前实机两次诊断中的空文通过不能代表质量稳定。此错误仍存在，计时修正不会修复它，也不能认为提高并发会解决它。

## benchmark 修正

只将 benchmark 的配额等待移到 Ktor request pipeline Before，早于请求定时器；许可仍覆盖完整响应保存。真实超时携带的嵌套取消 cause 在释放许可前关闭入口，排队请求不再发送；取消、上限、一次调用和失败不重试的约束保持。源码依据和离线复现方法见 [RESEARCH.md](RESEARCH.md)。
