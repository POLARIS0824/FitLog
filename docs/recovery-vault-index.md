# 原文恢复、资料库管理与来源索引

## 已实现行为

- Log 的恢复中心不依赖当前资料库连接。记录按原资料库分组，当前资料库优先；支持查看正文、继续编辑、确认删除本地记录和系统另存为。
- 恢复使用保存的资料库、目录、文件名和来源版本。异步恢复在读取和复制完成后校验选择代次，返回列表或重新选择后不再执行旧跳转。草稿必须携带 UUID 与原目录 URI；恢复前核对 UUID 对应的资料库定位器，不猜测当前目录。
- 导出采用 UTF-8，保留 BOM，写后读回校验；取消、失败或成功均不自动清除原草稿。Editor 也提供当前正文导出：文件选择器打开前将正文保存为独立本地快照，并在 SavedStateHandle 中保存快照标识；进程重建后继续导出同一快照，普通自动保存不会删除该快照。恢复导出快照也不覆盖同文件的其他未保存草稿。
- 本地草稿使用 AtomicFile，完成写入后再次核验内容。损坏记录单独提示，不妨碍其他记录。
- 每个文件的 JSON 备份保留最近一次写入前正文和待完成/已完成状态。待完成备份不被重试覆盖；备份恢复创建独立草稿，明确保存前不自动写回。
- 草稿文件键使用资料库 UUID；备份使用 `.backup.json`，只读取当前格式。损坏或缺少必要字段的记录明确提示。
- 资料库管理支持查看能力、切换/重新授权及确认解除连接。解除仅清除当前配置，保留文件、草稿、设置、索引和既有系统权限。
- Import 保存配置后进入 Log，扫描结果分别反馈；空目录扫描成功。今日日记不等待整库扫描。

## 索引与并发

Room `source-index.db` 仅保存来源身份、路径、权限能力、正文指纹、核验时间及扫描状态，schema 位于 `app/schemas`。数据库不保存正文或 AI 字段。schema 3 的身份列为 `vaultId`，格式变更通过破坏式重建处理，独立分析库及 Markdown 原文件不受影响。

完整扫描枚举 Markdown 后逐篇读取核验；相同资料库/文档 URI 更新同一来源。目录枚举完整才标记未发现来源为缺失；部分枚举或取消不标记缺失。正文读取失败保留旧指纹，并明确标记未核验。文档 URI 改变作为新来源处理，不猜测重命名关系。

索引协调器为使用 Application Context 的进程级单例，Activity 重建后的旧 Log 与新 Editor 共享每库锁和保存修订号。扫描结果事务提交，运行中显示上次结果。进程中断留下的扫描状态按中断显示；下次从头刷新。同库任务防重，取消及资料库切换使过期任务失效。保存回调与扫描提交以每库锁和保存修订号协调，较早的扫描结果不能覆盖较新的保存结果。

Log 保留搜索和排序，默认隐藏缺失文件，可显式显示。索引失败不改变原文件保存成功状态。索引存在不保证 SAF 授权或原文可读，不提供正文离线缓存。
