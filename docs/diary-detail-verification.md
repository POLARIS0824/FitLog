# 日记详情与持久化结果展示

Log 条目现在打开单篇日记详情，提供原文与分析结果两个视图。今日日记与恢复继续进入既有 Editor；详情中的编辑按钮也复用 Editor。详情仅读取已保存结果，不安装或调用模型，不发送模型请求，不自动确认或写回 Markdown。

## 读取与状态

- `DiaryAnalysisReader` 提供按 `SourceKey` 观察解析记录和确认记录的只读接口；仓库另提供 `readParses` 单次读取。业务对象包含尝试元数据及类型化候选，不暴露候选 JSON 或原始模型响应。
- 最近尝试、最近失败、最近成功候选、当前确认分别显示。失败不会遮住旧候选或用户修正；损坏候选明确报错，仍允许读取独立保存的确认记录。
- 详情身份固定为资料库 UUID、相对路径和原始 SAF 地址，不套用后来选择的资料库。按导航项保存 ViewModel；清理后的读取和过期分析观察不得发布状态。
- 首次打开、返回 Editor、回到前台和手动刷新时重新读取原文。归一化内容版本恢复文件 BOM 后仅归一化一次，与分析版本比较；字节指纹只用于原有文件读写冲突检查。
- 原文变化显示待更新；读取期间、不可读或哈希算法版本不同显示无法核验。证据仅作为解析所用旧版本的摘录展示，不使用旧坐标高亮当前原文。
- 候选与确认记录保留缺失字段和单边/总重口径。AI 候选显示逐字段推断与继承，确认结果只显示组级用户修改标记。零场次不会显示为休息日；部分结果不会断言没有其他训练。
- 默认和中文资源成对维护。页面沿用 App Scaffold 的系统边距，采用可换行操作区、双标签页和逐组延迟列表。分析库当前为 schema 2，安装前按[分析库升级说明](diary-analysis-database.md#本次开发安装)单独清理旧库。

## 真机检查清单（本轮未执行）

1. 在 Log 打开已有 Markdown，确认默认进入原文详情；原文可选择复制，分析页显示未解析而非休息日。空文件明确显示空内容。
2. 点击编辑，修改并保存后返回详情，确认重新读取新内容；确认今日日记与恢复仍直接进入 Editor，退出保护保持有效。
3. 连接只读目录，确认原文可浏览、编辑动作禁用；撤销权限或删除文件后刷新，确认读取错误清晰，恢复权限后可重试。
4. 若安装包已有候选和确认记录，关闭并重开应用，确认两者及最近失败仍可查看；候选不能覆盖用户修正。配置页与手动解析按钮尚未接入，不能把无结果当作提取验证通过。
5. 在外部编辑器修改已分析日记，回到应用或手动刷新，确认显示待更新；不可读时显示无法核验，仍保留已存结果。
6. 快速打开不同日记、返回及切换资料库，确认文件标题、原文、结果身份没有串页。
7. 检查中文与英文、深浅色、横屏、大字体及 TalkBack：操作区可换行，标签可选，长原文、证据和训练组可滚动，末尾内容不被系统导航栏遮挡。
