# Log 扫描与验收

SourceIndexRepository 是使用 Application Context 的进程级单例。Log 只观察索引；扫描读取真实 SAF 文件，不访问模型。当前索引为 Room schema 4，可删除重建。

## 触发与保存

- 应用首次读取配置后，对已配置的资料库扫描一次。Activity 重建、底部导航、返回 Log 和回到前台不触发扫描。
- 成功连接目录后显式扫描，包括 Import、今日日记引导中的连接和重新连接同一目录。读取配置及导航仍检查当前设置页身份。
- 用户手动刷新发起扫描；扫描运行中重复请求共享当前 Job，不排队补扫。失败只提示，后续扫描由用户刷新或下次打开应用触发。
- 每次扫描递归枚举 Markdown，并逐篇读取。没有元数据复用、节流、定时核对或持久化失效标记。
- 扫描与保存后的单条索引更新共用一个 Mutex。扫描持锁直到提交；扫描途中保存完成时，单条更新随后提交，不被较早扫描快照覆盖。
- Editor 的 Markdown 保存成功先独立成立。索引回调失败只提示；它不会改变原文保存结果，也不会自动扫描。

## 结果与失败

索引只保存 UUID、文档 URI、名称、相对路径、父目录、写入能力和来源状态，不保存正文、指纹或 AI 数据。扫描状态只保存完整、部分、失败及完成时间；扫描进度保存在内存。

只有目录枚举完整且所有文件读取成功，才标记未发现来源为缺失。部分枚举、正文读取失败、异常和取消均保留未发现来源。不可读条目显示 READ_FAILED；重复扫描更新同一 UUID/URI，不猜测改名映射。

切换或解除连接取消旧任务，旧提供方即使迟到返回也不能提交。新的扫描等待同一个 Mutex，任何时刻只有一个扫描实际执行。原文编辑冲突检查仍使用真实文件的字节指纹；详情读取及分析版本比较独立于索引。

## 真机检查清单

1. 按[分析库升级说明](diary-analysis-database.md#本次开发安装)准备安装；导入含子目录、空目录和只读目录，确认进入 Log 且扫描结果明确。
2. 从应用启动后切换底部页面、旋转屏幕、离开并返回应用，确认没有额外扫描；失败后等待也不会自动重试。
3. 外部新增、修改、移动或删除 Markdown，点击手动刷新，确认列表变化。外部变化在下一次显式扫描前允许暂未反映。
4. 在扫描途中编辑并保存日记，返回 Log，确认单条保存结果最终可见；原文保存和草稿保护继续有效。
5. 扫描途中切换或解除资料库，确认旧结果不替换当前列表；撤销权限或制造读取失败后，未发现记录不被误判缺失，恢复权限后可手动刷新。

本轮未运行设备验收或付费模型调用。
